# M3.5 owner-content preservation inventory

This inventory precedes the preservation helper. The boundary is the live,
owner-authenticated control API and independent published site. The helper may
append owner revisions through those APIs; it must never rewrite database rows,
publication pointers, or history. The full gate remains the acceptance test.

| Condition | Observable outcome |
| --- | --- |
| Preflight snapshot | A mode-0600 private file captures the exact latest private draft and preview, latest approved snapshot and appearance, latest published ID and slug, plus their IDs and revisions. Publication must reference the latest approval. No public artifact contains draft text or credentials. |
| Incomplete or changed approval | Snapshot rejects absent or unpublished publication, an approval that differs from the published approval, or displayed readiness/facts that a new review cannot reproduce without changing owner-visible values. It makes no mutation. |
| Gate made no owner-content change | Restore reads the three heads, verifies equality with the snapshot, records a private no-op receipt, and appends no revision. |
| Gate changed content with recorded IDs | Restore accepts only draft, approval and publication IDs proven by that exact gate manifest or a prior preservation receipt. It appends a new draft of the original approved content, reviews and approves that exact revision, publishes to the original slug, waits for the new publication to become the current published ID, then appends the original private draft and preview last. Owner-visible public and private values match the snapshot; prior revisions remain readable. |
| Stale or unknown head, conflicting write, network loss or timeout | Before each write, an unexpected head aborts without another write. `If-Match` rejects a concurrent draft save. A mode-0600 receipt records each successful API ID so retry can verify and resume only from its own exact head. Publication polling has a finite deadline and does not claim completion from a queued response. |
| Authentication or ownership failure | The helper aborts without logging a password or token, and revokes its session on exit. It never uses another account or expands the preview access boundary. |

The preservation exercise must use an explicit focused E2E artifact before a
full gate. A failed or incomplete gate artifact remains failure evidence; it is
not rewritten by content restoration. The caller verifies the artifact's source,
run ID and receipt separately. New revision and publication IDs are expected;
the receipt records those IDs and checks visible content equality.
