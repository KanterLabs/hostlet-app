# M3.5 restricted preview contract

This is the selected deployed boundary for HOST-246–HOST-248, written before
implementation. [M3-HANDOFF.md](M3-HANDOFF.md) remains the accepted local,
owned-fixture evidence. M3.5 composes those paths for a restricted preview; it
does not change the `owned_fixture_only`, `production_ready=false` runtime
decision or authorize customer admission, payment, general sign-up, provider
purchases, or M4. [M3.5-SCENARIOS.md](M3.5-SCENARIOS.md) defines acceptance.

## Placement and access inputs — HOST-246

The requested entry name is `beta.hostlet.cloud`, but it is occupied by the old
Hostlet (HTTP 530). Before any mutation, record the observed DNS, TLS, route,
origin, process and data ownership and the exact current route target. Select
an independently owned deployment target and an access mechanism only after
this read-only inventory. Treat host, public path, private origin, static-site
host, route target, TLS issuer and secret delivery as configuration inputs; this
document assigns no live host, path, credentials or provider. Use separately
configured HTTPS origins; a candidate sibling host under the existing domain
must have its own validated DNS and certificate coverage. Do not assume a
wildcard certificate covers deeper subdomains. Record the exact route target
before change. After owned staging and health checks, a protected temporary
HTTPS cutover may run inside the gate; exercise exact reversal to the recorded
target and, if needed, reapply the preview target to finish the gate. A failed
gate restores the recorded route. Retain a final preview route only after both
clean gates. A mismatch, unknown owner or inability to restore the original
route blocks cutover. Existing databases, disks, containers, registries,
subscriptions and old Hostlet state are preserved.

The preview uses valid HTTPS and a restricted owner entry. An unauthenticated
browser cannot load the private dashboard or reach its API, even by calling a
network-accessible origin or guessing a URL; a signed-in non-owner cannot read
or change the seed owner's resources. Public sign-up is denied at the deployed
boundary. The chosen edge restriction and application session are recorded and
independently exercised. Bootstrap and workers may use the private loopback API
under their scoped credentials; it is never a public edge bypass. Health
endpoints may expose only bounded status. The independently served static
portfolio remains behind the same owner access boundary. Owner approval
controls its content; publication never grants anonymous access. Credentials
are injected into only the service that needs them, never into source,
artifacts, guest builds, URLs or browser bundles.

## Selected placement decision

Use the existing development/test VM with a dedicated preview service identity,
private persistent state, pinned binaries/images, and explicit unused loopback
ports. A new dedicated outbound Cloudflare Tunnel reaches only the preview
origin. Route exactly `beta.hostlet.cloud`, `beta-demo.hostlet.cloud` and
`beta-portfolio.hostlet.cloud`; leave the legacy tunnel, apex, wildcard and
unrelated edge services unchanged. The provider readback confirms an exact
legacy beta record and no exact records for the two sibling names. Private
before-state records retain exact IDs and route values; they are not source.
The preview remains a development installation without a paid availability SLA.

Use Caddy's HTTPS-edge Basic Authentication with fresh preview-only owner
credentials. The preview build sends its application session in
`X-Hostlet-Authorization` so the browser can retain the independent Basic
Authentication header. After successful edge authentication, translate this
header to `Authorization` only for the control API and remove the alternate
header. Strip edge credentials before forwarding to demo or static services.
The normal development build continues using standard Bearer authentication.
Block `/v1/accounts` at the preview edge; bootstrap uses the private loopback
API. All three exact hosts require the gate. Unknown hosts fail closed.
Cloudflare provides public TLS; origin listeners bind loopback and are reached
only by the dedicated connector. HTTP requests redirect to HTTPS before any
credential entry. Do not forward Basic credentials over a public HTTP origin.

Store generated credentials in service-specific private files, delivered to
managed processes without shell arguments or source inclusion. Give the owner
a private local access handoff; never put passwords in URLs or task artifacts.
The control database and project database use distinct credentials and owned
persistent volumes. Runtime keeps the M3 512 MiB/quarter-core/128-process
limits and existing network policy. Build resource limits remain those of the
pinned disposable-VM profile. Managed service restarts use a finite retry budget
and readiness deadlines; a routine restart never rebuilds, migrates or reseeds.
On schema-6 reuse, migration-specific acceptance is N/A with recorded evidence.
Backups restore only into newly owned isolated targets during verification.

## Owned composition — HOST-247

Run the real React/Vite dashboard against the real control HTTP API and durable
platform PostgreSQL. Seed one synthetic owner, one project with a selected exact
source revision, and a live owned Node plus project PostgreSQL demo through the
M3 build, runtime and release boundaries. The portfolio references that project
without consuming a live-project slot. Its narrative and public links come from
a saved owner revision and explicit approval; source access or a live deployment
alone never publishes them. The published site is immutable static output served
independently of dashboard, control, source provider and demo availability,
through a separately configured HTTPS origin protected by the owner access gate.

Bootstrap is idempotent and keyed to stable owned identifiers and exact source
digests. It creates missing seed records, then reports existing records without
overwriting owner edits, approval decisions, project data, release history or
the live site pointer. A partial seed or interrupted bootstrap can be rerun to
one coherent result. Ordinary owner edits and application writes do not require
a pre-change backup. A schema/storage format upgrade or deployment change
affecting populated state requires a fresh verified backup and an isolated
populated compatibility trial before the live change; startup never silently
migrates or resets either store. M3.5 is expected to reuse schema 6. If no
qualifying change occurs, record migration-specific checks `N/A` with evidence;
still prove a real populated backup, isolated restore and restart persistence.
Retained release compatibility and rollback operate against current data.

Processes use managed restart with bounded attempts and explicit readiness.
An unhealthy API, builder, runtime, database or publisher fails visibly and
does not advance a route or claim a working demo. Restart preserves durable
owner edits, tenant rows, approval and publication pointers. The preview keeps
control, builder, runtime, project database, and static publisher permissions
and network scopes separate as in M3. The dashboard, demo and portfolio use
configured separate HTTPS origins under the selected access policy. A fresh
authorized portfolio load needs no API or demo request after access is granted.

## Gate, stop and recovery — HOST-248

The deployed gate proves browser sign-in, an owner edit saved across managed
restart, exact revision review/approval, a working demo with a persisted
database write, and a static portfolio that still loads after dashboard,
control and demo are stopped. It tests access denial and the exact route
reversal. Run `make check` separately and two clean full E2E gates on the same
clean implementation commit, with private artifacts and independently verified
external `SHA256SUMS` receipts per [TESTING.md](../TESTING.md). A failed full gate
is retained, reported and followed by only exact owned cleanup; it does not
count toward the two passes or trigger an automatic retry. The handoff records
both receipt hashes, route before/after/reversal evidence, surviving resources,
and unverified production claims. Stop at HOST-248 before M4.

The preview may retain explicitly inventoried owned services, databases,
backups and static artifacts needed to keep it available. Every temporary
resource has an owner label or equivalent exact identity and a recorded cleanup
result. Cleanup never sweeps a shared namespace or removes an existing old
Hostlet resource. On rollback, preserve populated data and approved static
artifacts, restore the exact prior route, and report any resource intentionally
retained for later operator action.
