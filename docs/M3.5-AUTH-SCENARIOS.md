# M3.5 sign-in rejection scenario

This inventory precedes the dashboard copy change. The scoped boundary is the
restricted preview in a real browser, using the owned synthetic account and the
deployed `POST /v1/sessions` API. Existing authenticated-request behavior and
general error messages remain part of the check. No isolated test is needed;
the browser and HTTP boundary can observe the failure.

| Failure or outcome | Observable result |
| --- | --- |
| Wrong password, or unknown email, with a well-formed sign-in request | `POST /v1/sessions` returns HTTP 401. The browser keeps `auth-form` visible, does not show `signed-in-user`, and shows `Email or password is incorrect. Please try again.` in `onboarding-notice`. Both rejection causes have the same copy; no account existence is disclosed. |
| Correct password after the rejected attempt | The same browser signs in, shows `signed-in-user`, and can continue the owned preview journey. The rejection must not leave a stale error or block retry. |
| Expired or invalid token on an authenticated request, including `GET /v1/me` | The browser clears the session and shows `Your session has expired. Please sign in again.` The sign-in form returns. |
| Rate limit, service error, timeout, or network failure while signing in | The existing rate-limit, temporary-unavailability, timeout, or unreachable message remains visible. Only HTTP 401 from session creation gets credential-rejection copy. |
| Malformed form values | Browser constraints and the API's existing validation response apply; no credential-rejection claim is made for a non-401 response. |

The sign-in attempt is a single request with no client retry or session token on
rejection. Concurrent sign-in submissions remain disabled while the request is
in flight. The E2E runner should assert the HTTP status and browser UI, then use
valid credentials for the normal journey. It must redact passwords, tokens and
private data from retained artifacts. Other restart, recovery and durable-data
checks remain in the M3.5 gate; this copy change does not alter those boundaries.
