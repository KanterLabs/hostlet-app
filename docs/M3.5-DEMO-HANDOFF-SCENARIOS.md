# Restricted M3.5 demo handoff scenarios

This is a scoped, repeatable browser check for showing Shane the already
installed private preview. It does **not** satisfy HOST-248 acceptance or
replace either clean full M3.5 gate. It may append only a synthetic owner draft
revision and a uniquely named demo row. It does not approve or publish that
draft, change provider routing, restart services, seed fixtures or restore data.
The parent owns route cutover, service readiness, backups and final review.

## Failure inventory before implementation

| Boundary | Failure to retain | Required observable result |
| --- | --- | --- |
| Public route propagation | Anonymous root 401 can appear before the same host serves protected HTML; dashboard API or one portfolio path can still return Cloudflare 530/1033. | Under one 300-second deadline and continuous 20-second window, require all seven exact probes together: three anonymous root 401s, malformed authenticated dashboard `/v1/me` 401 `authentication_required`, and Basic-auth dashboard root, demo root and the authoritative current published portfolio path each 200 `text/html`. Record only safe status, MIME, Cloudflare and transport metadata. Do not retry behavioral checks after readiness. |
| Fresh browser and save | Old page state can look loaded, the save button can be disabled, or a POST can fail while the UI still contains typed text. | Fresh Chromium signs in as the owner and shows the selected owned project/editor. A distinct synthetic introduction is typed; the enabled save sends an actual POST that returns 201 with a numeric revision. Reload shows the exact value, and the owner API reports that same revision and value. Retain safe request/response/notice state, no bodies or credentials. |
| Working demo | A browser can display an old row or a transient unsaved row. | Create a uniquely named row through the demo form, observe its actual POST 201 and row ID, reload in Chromium and find the same ID/name, then cross-check through `/api/items`. |
| Approved static portfolio | The newly saved private introduction is not approved and must not be represented as published. A stale or broken link can look like a working home page. | Read the currently published ID/slug from the owner API. Load its protected static home and project detail in Chromium with 200 HTML responses, then follow a configured HTTPS demo link and load the demo form. Do not reapprove or republish. |
| Failure and artifact boundary | A timeout, HTTP error or browser crash can erase the useful observation or accidentally retain secrets. | Flush bounded safe event metadata and assertion results before cleanup; revoke the run-created local and browser owner sessions and close only the run-owned Chromium profile. Produce mode-0600 manifest/report/source copies and a SHA256SUMS receipt on pass or failure. Record installed binary digests separately from harness HEAD/hash; fixture rebuild and toolchain build evidence are N/A for this existing release. Reject a colliding run ID and stop on the first failed assertion; never mutate provider or service state as cleanup. |

Run `node e2e/beta/demo-handoff.mjs --config <private-config> --edge-credentials <private-edge-credentials>` with optional `--run-id <unique-id>`, `--chromium <binary>` and `--manual-credentials <private-file>`. The script records the exact input paths and a repeat command with a fresh generated run ID in its private artifact. Credential values are read only from the existing mode-0600 files; the handoff may name a manual credential file path, never its contents.
