# M3.5 provider-read reliability scenarios

The second final gate failed after `reverse` succeeded because the following
`cloudflare.py status` read exited 2. Its stderr was lost, so the cause remains
unknown. This assignment changes read failure handling and diagnostics only.
The live preview and owned provider resources are outside these checks.

## Failure inventory before implementation

| Boundary or failure | Expected observable outcome | E2E boundary |
| --- | --- | --- |
| Malformed private input or journal | Exit 2 with a safe input code; no provider request or write | Invoke the CLI with private synthetic files. |
| Token rejection, ownership mismatch, changed guard or record metadata | Exit 2 with provider/guard code; no retry after a definitive response and no mutation | Invoke the CLI against the real API, where safe, or inject a definitive response at the outbound HTTP boundary. |
| A GET transport timeout or connection failure | At most three attempts in the deadline, then a safe failure or successful read; no mutation | Fault a real outbound GET at a local forwarding proxy. |
| A GET response trickles bytes continuously past the socket timeout | A 12-second wall-clock timer ends the read with a safe transport refusal; no second request starts after the deadline | Return headers and a slowly trickled body from the local fault proxy. |
| A GET HTTP 429 or 5xx, with or without Retry-After | Retry within deadline and bounded Retry-After; report status and attempts on exhaustion | Fault a real outbound GET at a local forwarding proxy. |
| A GET HTTP 4xx other than 429, provider `success: false`, or malformed JSON | Exit 2 after one attempt; no retry | Inject the response at the outbound HTTP boundary. |
| A write transport failure or HTTP 429/5xx | Exit 2 after one attempt; preserve journal pending state for explicit readback/resume | Exercise only with an isolated owned fixture in a separately authorized gate. Do not inject into live preview. |
| Duplicate delivery, ordering, and concurrent CLI calls | Existing private lock and journal ownership rules apply; no blind write replay | Existing route gate crosses the provider and journal boundaries. |
| Cancellation, deadline, partial failure, and cleanup | Deadline bounds a GET, failure emits one parseable safe stderr object, lock is released; entry route remains handled by the parent gate cleanup | CLI process plus forwarding proxy, followed by a second read and the gate's exact cleanup check. |
| Persistence, restart, and retained state | No journal schema or stored provider state change from a read retry | Inspect private journal before and after the isolated read check. |

These are E2E boundary checks; no isolated unit check or unit test is needed.

## Proposed focused acceptance

Use the existing private preview configuration and credentials only in a gate
approved by the primary agent. Put a local forwarding/fault proxy between the
CLI and the real Cloudflare endpoint, intercepting only outbound GET responses.
Run `status` with the real private journal and compare its stdout to an unfaulted
status. Cases: one dropped GET then a real successful response; one 429 with
`Retry-After: 1` then success; three transient failures to exhaustion; a
definitive 403; malformed successful response. Assert exit status, structured
stderr fields, number of GETs, deadline, unchanged journal hash, and zero
forwarded writes. Perform an unfaulted provider read afterward and verify exact
preview route and no pending mutation. Never route a mutation through the fault
proxy during this check.

The focused runner is `python3 e2e/beta/provider-read-boundary.py
--cloudflare-config /private/cloudflare-config.json`. It creates a fresh private
`artifacts/e2e/M3.5/<run-id>/` directory before checking prerequisites and
retains a report, manifest, copied runner, and external SHA256SUMS receipt on
both pass and handled failure. The exact repeat command uses a fresh automatic
run ID. Scoped token variables are inherited by child processes, never passed
in arguments or written to the artifact. The launcher imports the real CLI,
changes only its in-process API base to an ephemeral localhost proxy, and calls
`main()` with `status`; the proxy forwards successful GETs to the real provider.
It rejects every non-GET and suppresses HTTP access logs. Faults affect the
first provider GET only, so later GETs prove actual upstream readback.

The runner's cases are: unfaulted baseline; one dropped connection, one 503,
and one 429 with Retry-After 1 followed by successful real read; three 503s
ending in exhaustion; one 403, malformed JSON, and `success: false` ending
immediately; one 429 with Retry-After 60 ending immediately without an early
retry; one slow-trickled response stops at the 12-second wall-clock deadline.
Successful cases must reproduce baseline stdout exactly. Each case
checks count and method of outbound requests, safe retry/error events, exit
code, elapsed time, zero writes, and byte-identical private journal. The final
unfaulted read must still report the exact preview route and no pending
mutation. No case publishes, mutates the route, or accesses customer data.

On failure, stderr is one JSON object with schema
`hostlet.beta.cloudflare.error/v1`, `command`, `code`, `method`, `httpStatus`,
and `attempts`. A transient GET attempt that will be retried emits a
`hostlet.beta.cloudflare.retry/v1` object with `command`, `code`, `method`,
`httpStatus`, `attempt`, and `elapsedMs`, even when the next attempt succeeds.
The fields contain only fixed allowlisted values or numbers; there is no
request URL, provider identifier, token, or exception text. Failure codes are
`transport_failure`, `http_retry_exhausted`, `http_failure`,
`provider_rejected`, `response_failure`, `guard_refusal`, and
`input_or_journal_malformed`.

Only GET is retried, at most three attempts within a 12-second wall-clock
deadline, with a four-second socket timeout per attempt. A valid Retry-After
delay is honored if the next attempt fits the deadline; otherwise the read
fails at its current attempt. Non-retryable HTTP responses and semantic
provider or ownership refusals fail immediately. Writes have one attempt and
retain the existing pending journal for explicit readback and recovery. The
null/empty DNS comment equivalence applies only to the accepted legacy beta
record; apex and wildcard guard records remain strict.
