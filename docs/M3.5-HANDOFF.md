## Recovery diagnosis — 2026-09-25

Two focused browser captures on the retained installation, an invalid save
and the normal introduction edit, both reached the API and returned HTTP 400
`malformed_if_match`. The field contained the intended value and the save
button was enabled. Both artifacts retained the allowlisted response, editor
state and cleanup; their checksums were independently verified and routes
restored. These are diagnostic failures, not full acceptance attempts.

Boundary readback isolated the cause: the origin and local edge return ETag
`"1"`, while the public compressed response returns `W/"1"`; identity encoding
retains the strong tag. The UI forwards the received validator and the strict
API parser rejects the weak one. [Cloudflare documents this compression
behavior](https://developers.cloudflare.com/cache/reference/etag-headers/).
The scoped correction is to preserve private preview responses with
`Cache-Control: private, no-store, no-transform`, retaining strict revision
checks and stale-write rejection. The first deployed correction was overwritten
by outer middleware; see the stopped recovery result above.
